## HoneyBadger 0.8.1

Security scanner for skills, tools, and MCP servers used by AI assistant runtimes.

**HoneyBadger don't care. HoneyBadger checks anyway.**

This release (v0.8.1) publishes the v0.8.0 preparation content, including the README status repair; the v0.8.0 tag remains at its original commit as a preserved, un-released artifact.

### Highlights

- **Evidence receipts and secure scanner supply-chain checks (#117):** receipts describe the scan subject, versions, checks actually run, findings, exceptions, build-action pins, and published assets. A receipt SHA256 is a content digest, not a signature. Local artifact verification is `verified` only when the calculated digest matches a trusted registered baseline; remote asset fetch-and-compare and signed receipt export remain unimplemented.
- **Ordinal paranoia gates and CVE enrichment (#118):** `off` and `minimal` tiers do not invoke LLM verdict processing. High-EPSS enrichment may raise or annotate severity but cannot downgrade a CRITICAL CVSS result when KEV is absent.
- **Self-describing attestation indicator (#118):** result events now expose `attested_basis`. `workflow_configured` means attestation workflow infrastructure was detected; it does not mean a signature was cryptographically verified. Source scans do not verify release signatures.
- **Audit provenance (#119):** additive audit-record provenance includes source/rules digests, rule directory, ignore trust decision, suppression decisions, and per-check completion/failure status; existing JSONL records remain decodable.
- **Dependencies (#115, #116):** CodeQL action and `mcp-go` were updated; no user-facing scanning behavior change is intended from these dependency updates.
- The release self-check now validates its complete NDJSON output, requires exactly one top-level result, and cross-checks the scanner exit status before accepting PASS/WARN. Release notes are authored locally; no AI-generated notes are used.

### Install

```bash
# Go install
go install github.com/famclaw/honeybadger/cmd/honeybadger@v0.8.1

# Docker
docker pull ghcr.io/famclaw/honeybadger:0.8.1

# Binary (Linux amd64)
curl -fsSL https://github.com/famclaw/honeybadger/releases/download/v0.8.1/honeybadger-linux-amd64 -o honeybadger
chmod +x honeybadger
```

### Verify

```bash
# Verify checksum signature (cosign signs SHA256SUMS, not individual binaries)
cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.bundle \
  --certificate-identity-regexp ".*famclaw/honeybadger.*" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

# Verify binary integrity via checksums
sha256sum --check SHA256SUMS

# Verify Docker image signature
cosign verify ghcr.io/famclaw/honeybadger:0.8.1 \
  --certificate-identity-regexp ".*famclaw/honeybadger.*" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

### Release security artifacts

The publication workflow signs `SHA256SUMS` with keyless Sigstore cosign and attests the checksums file with GitHub build provenance. It publishes SPDX SBOMs and signs container images. These signatures and attestations are generated by the release workflow at publication; this local preparation does not claim to contain signed artifacts.
