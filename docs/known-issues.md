# Known Issues

This document tracks known issues with HoneyBadger's behavior that users should be aware of.

## LLM Verdict Parser Tolerates Trailing Content

The LLM verdict parser now tolerates trailing content that may be generated by some LLM backends after a complete, valid JSON verdict. Previously, if an LLM response contained a complete JSON verdict followed by additional prose (e.g., HTML/JSX-like syntax in source files), the strict JSON parser would reject it with the error:

```
llm verdict parse: invalid character '<' after top-level value
```

This is a workaround for LLM backends that generate extra content after the JSON verdict. The parser now attempts to extract the first balanced JSON object from the response content, allowing such responses to be parsed successfully.

## GitHub Rate Limiting

`GitHubFetcher.Fetch` in `internal/fetch/github.go` does one HTTP request per file with no bulk-clone fallback, so unauthenticated runs (60 requests/hour) hit the GitHub rate limit almost instantly on non-trivial repos and then silently crawl through backoffs with no progress output.

**Workaround:** Set `GITHUB_TOKEN` to increase your rate limit to 5,000 requests/hour.
